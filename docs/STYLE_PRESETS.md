# Illustration Style Presets v1.0

## 目的

Kid Story 不讓每一本書都重新即興決定畫風。正式商品提供固定的「官方繪本風格預設」，讓顧客可以直接選擇，同時讓角色一致性、場景複雜度與整本書的視覺品質更容易自動化與 QA。

目前正式保留 3 種風格：

- S1｜粗線平圖
- S2｜拼貼繪本
- S3｜粉彩童話

這三種為 Kid Story 自有的高階視覺規格，不以複製特定插畫家或單一出版作品為目標。

---

# S1｜粗線平圖

## 一句話

用簡單粗線與大色塊，把孩子的動作和故事重點畫得一眼就懂。

## 適合

- 3–5 歲幼兒
- 動作明確、任務感強的故事
- 需要孩子快速理解「發生什麼事」的主題
- 喜歡活潑、童趣、清楚視覺的家庭

## 視覺規則

- 線條：偏粗、自然、不完全筆直
- 色塊：大面積平塗，細節少
- 色彩：低至中飽和，避免螢光色
- 陰影：極少，通常只有簡單色差
- 背景：高度簡化，只保留故事必要物件
- 人物：輪廓辨識優先於臉部細節
- 表情：清楚、稍微誇張但不動漫化
- 紋理：少量紙張或手繪筆觸即可

## 複雜度

低。

每個畫面原則上只保留：
- 1 個主要角色
- 1 個主要動作
- 1–3 個必要環境物件

## 禁止

- 寫實肌膚
- 複雜頭髮光澤
- 電影光影
- 大量背景裝飾
- 3D 公仔感
- 高精緻商品插畫感

## 關鍵字

大色塊、粗線、平面、童趣、清楚、乾淨、簡化。

---

# S2｜拼貼繪本

## 一句話

像孩子和爸媽一起用紙、剪貼與顏料做出來的一本故事。

## 適合

- 想要「手作感」最強的家庭
- 想降低 AI 精緻感
- 奇想、冒險、生活觀察類故事
- 喜歡每一頁都帶一點作品感與收藏感的家庭

## 視覺規則

- 角色：簡化輪廓，可用剪紙感色塊組成
- 紙材：可見不同紙張、纖維、撕邊或剪裁邊緣
- 色彩：低飽和自然色，允許少量跳色
- 線條：可搭配蠟筆、鉛筆或不規則手繪線
- 背景：以拼貼色塊建立，不追求透視精準
- 光影：幾乎不使用寫實光影
- 物件：可稍微像孩子手工作品，不需完美對稱

## 複雜度

中低。

視覺可以有層次，但不是靠增加物件，而是靠不同紙材／色塊層疊。

## 禁止

- 寫實攝影拼貼
- 過度精細紙材紋理
- 立體陰影做得像商業海報
- 大量裝飾貼紙
- 每一頁換不同素材語言

## 關鍵字

剪紙、拼貼、手作、紙感、不完美、童趣、低飽和。

---

# S3｜粉彩童話

## 一句話

柔和、帶空氣感的童話繪本，重點放在孩子的情緒與故事氛圍。

## 適合

- 睡前故事
- 情緒、害怕、第一次嘗試、家庭變化
- 希望畫面比較溫柔的家庭
- 喜歡童話感，但不希望華麗夢幻的家庭

## 視覺規則

- 線條：細而鬆、部分輪廓可融進色塊
- 媒材：乾粉彩／粉蠟筆感 + 很淡的水彩暈染
- 色彩：低飽和、霧感、柔和暖色為主
- 背景：大量留白與柔化環境
- 人物：臉部簡化，但保留足夠辨識度
- 光影：柔和，不做高反差
- 氛圍：安靜、有一點童話，但仍生活化

## 複雜度

低至中。

畫面可以有氛圍，但細節量必須受控；不能因為「童話」就增加大量花草、星光與魔法粒子。

## 禁止

- 公主電影感
- 大量閃光／粒子
- 夢幻城堡式背景堆疊
- 3D 柔光角色
- 過度細膩臉部與皮膚

## 關鍵字

粉彩、柔和、留白、童話、低飽和、安靜、溫暖。

# 顧客選擇方式

在故事內容與主角模式基本確認後，系統詢問：

> 接下來可以選擇整本故事的畫風。三種畫風不會改變故事內容，只會改變你看到的視覺感覺。

提供三張同一個中性示範場景的 Style Card：

1. **粗線平圖**｜清楚、活潑、童趣
2. **拼貼繪本**｜手作、紙感、有作品感
3. **粉彩童話**｜柔和、安靜、有童話感

顧客直接點選其中一種即可。

不得只用文字名稱讓第一次接觸的顧客盲選；正式產品應搭配固定 Style Preview。

---

# Style Lock

顧客確認後建立：

`style_id = S1 | S2 | S3`

從 Character Reference Sheet、三張 Visual Test、正式故事頁到封面都必須使用同一 style_id。

同一本故事不可中途混用不同風格。

若顧客要求重選畫風，應視為重新生成視覺資產，而不是局部修改。

---

# Character Lock 與 Style Lock 分離

必須分清楚：

- Character Lock = 這個孩子／角色是誰
- Style Lock = 用什麼繪畫語言呈現

因此同一個 Character Lock 理論上可以套 S1、S2、S3 做三張 Style Preview，而不應改變：

- 髮型
- 臉部辨識特徵
- 年齡感
- 固定服裝
- 招牌動作

這是未來自動化的重要架構。

---

# 自動化建議

每筆訂單保存至少以下欄位：

```json
{
  "protagonist_mode": "A|B|C",
  "likeness_level": "L1|L2|L3",
  "photo_mode": "P0|P1|P2",
  "style_id": "S1|S2|S3"
}
```

生成流程：

Intake → Story → Character Lock → Style Choice → Style Lock → Reference Sheet → 3 Visual Tests → Full Book。

Style Choice 應在正式大量生圖前完成，避免生成後才重新選風格造成成本浪費。
