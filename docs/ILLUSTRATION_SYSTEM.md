# Illustration System v0.3

## 目的

Kid Story 的正式成品不是純文字，而是「圖像化睡前故事書」。插畫系統的目標是：讓 3–6 歲孩子容易進入情境，同時讓角色在不同頁面之間保持一致，並把 AI 感降到最低。

## 產品原則

1. 正式成品必須有圖；純文字只作為內部草稿與家長預覽。
2. 圖像要先服務故事理解，再服務美感。
3. 不追求高細節 3D、電影感或過度光影。
4. 背景保持簡潔，讓孩子一眼知道「主角正在做什麼」。
5. 一頁只表達一個主要動作或情緒。
6. 不直接複製既有卡通／電影角色；若孩子喜歡某作品，只抽取高階敘事元素，例如勇敢、任務、團隊、冒險。
7. 是否讓孩子本人出現在故事中，由家長選擇，不預設哪一種比較好。
8. 是否提供照片為選填；Photo-free 仍是完整正式商品。
9. 正式視覺只提供鎖定的官方 Style Presets，不每次自由即興定義畫風。
10. 角色設定與畫風設定必須分離：Character Lock 決定「是誰」，Style Lock 決定「怎麼畫」。

## 主角模式

### A｜孩子本人

故事主角就是孩子本人。可用 Photo-free 或 Photo-assisted。

### B｜孩子靈感原創角色

保留孩子的個性、喜好、情境與部分外型特徵，但角色不是直接複製本人。

### C｜孩子不直接出現

改由原創小孩、動物或象徵角色承載故事情境。

## 外型相似度

- L1：感覺像就好
- L2：希望看得出來是他
- L3：不希望太像本人

即使選 L2，仍採插畫化，不承諾寫實肖像複製。

## 官方 Style Presets

詳細規格見 `docs/STYLE_PRESETS.md`。

### S1｜粗線平圖

清楚、活潑、童趣。粗線條 + 大色塊 + 極少細節，讓幼兒一眼理解角色動作。

### S2｜拼貼繪本

手作、紙感、有作品感。以剪紙／拼貼色塊和不規則手繪線建立畫面，刻意保留不完美感。

### S3｜粉彩童話

柔和、安靜、有童話感。以乾粉彩／粉蠟筆 + 淡水彩暈染、低飽和與留白為核心。

## Style Choice

在正式生成 Character Reference Sheet 前，家長需要選擇 S1 / S2 / S3 其中一種。

正式產品必須搭配固定 Style Preview，不能只顯示文字名稱讓顧客盲選。

Style Choice 不改變：
- 故事內容
- Character Lock
- 孩子的髮型／辨識特徵
- 固定服裝
- 招牌動作

只改變繪畫語言。

## Style Lock

確認後保存 `style_id`：

- S1
- S2
- S3

從 Character Reference Sheet、Visual Tests、封面到全書插畫全部使用相同 Style Lock。

同一本書不可混用不同畫風。

## Character Lock

每一本書在生圖前必須建立 Character Card。以下欄位一旦確認後，全書鎖定：

- 大致年齡
- 髮型與髮色
- 臉部輪廓（僅風格化描述）
- 主服裝
- 鞋子
- 主色系
- 招牌動作
- 個性表情範圍
- 是否有固定物件／玩偶

同一本書不得自行改變：

- 髮長
- 衣服款式與主要顏色
- 鞋子
- 臉部基本比例
- 年齡感
- 招牌動作特徵

## Photo-free Mode

不提供照片也能完成正式繪本。

家長只需選擇：

- 髮長：短／中／長
- 髮型：直髮／微捲／綁髮等
- 髮色
- 膚色範圍
- 常穿顏色
- 是否戴眼鏡
- 其他明顯但不敏感的外觀特徵

成品目標是「讓孩子覺得像自己」，不是寫實肖像。

## Photo-assisted Mode

### P1｜1 張大頭照

家長可主動提供 1 張近期、清楚的大頭照，協助角色更接近孩子。

適用目標：L2「希望看得出來是他」。

### P2｜2–3 張參考照（未來 Premium）

可包含正面、45 度／側面、日常穿著參考，用於提升一致性。

### 照片規則

- 家長主動選擇，不得強迫
- 不提供照片不影響完成正式商品
- 上傳前說明用途、保存期間與刪除方式
- 不把照片或可辨識影像提交至公開 GitHub
- 未經另行明確授權，不作為公開案例或行銷素材
- 仍採插畫化，不製作寫實人像
- 正式對外收照片前，必須先完成可執行的保存與刪除流程

## Character Reference Sheet

正式故事頁之前，先建立同一角色的參考圖，至少包含：

- 正面
- 45 度
- 側面
- 背面
- 4–6 種核心表情
- 2–3 個招牌動作
- 固定服裝與重要物件

若使用 Photo-assisted，Reference Sheet 是把照片轉成「可鎖定的插畫角色」的中介層。後續故事頁應引用 Character Lock，而不是每頁重新依賴照片自由生成。

## Page Composition

建議正式版：封面 + 14–16 個內頁畫面。

每頁原則：

- 文字 1–4 句
- 主角 1 個主要動作
- 最多 1 個故事焦點物件
- 留足文字區域，不把關鍵角色壓在版心或裁切邊
- 連續頁面需有視覺節奏：近景 / 中景 / 全景交替
- 無論選 S1 / S2 / S3，細節量都必須受到控制

## Story-to-Image Pipeline

1. Intake 完成
2. 確認主角模式 A / B / C
3. 確認相似度 L1 / L2 / L3
4. 確認照片模式 P0 / P1 / P2
5. Story Plan 確認
6. Draft 確認
7. Page Script 拆頁
8. Character Card 鎖定
9. 顧客選擇 S1 / S2 / S3
10. Style Lock
11. 生成 Character Reference Sheet
12. 先測 3 個關鍵場景：日常、故事核心動作、解決方法
13. 一致性與可讀性通過後再做全書
14. 視覺 QA
15. 排版成電子繪本

## 視覺 QA

每頁檢查：

- 角色是否仍像同一個孩子／同一個角色
- 若選 L2，家長是否仍能辨識「像孩子」
- 是否維持同一 Style Lock
- 是否符合該 Style Preset 的細節量與媒材語言
- 年齡感是否一致
- 衣著是否一致
- 左右手／肢體是否自然
- 畫面是否真的符合該頁文字
- 是否多出不必要角色或物件
- 是否過度華麗搶走故事焦點
- 是否出現文字亂碼
- 是否有明顯 AI 常見錯誤

全書檢查：

- 主角辨識度是否穩定
- Style Lock 是否穩定
- 關鍵場景是否看得懂
- 核心口訣或行動是否能只靠圖片理解
- 封面是否能一眼知道是這個家庭的故事

## Founder Beta 驗證指標

特別觀察：

- 孩子是否會主動指圖
- 是否因圖片理解故事情境
- 是否辨識／接受「這是自己」或「這個角色像自己」
- 角色相似度是否增加代入感
- S1 / S2 / S3 哪一種最適合孩子理解
- S1 / S2 / S3 哪一種最低 AI 感
- S1 / S2 / S3 哪一種家長最想收藏
- 哪一頁停留最久
- 哪一頁沒有興趣
- 是否能從圖片說出正在發生什麼
- 第二次閱讀時是否能預測下一個動作或口訣
